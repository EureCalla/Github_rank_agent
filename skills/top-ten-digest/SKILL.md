# 十大乾貨（精選 10 個）

## 觸發

使用者在 `Github_rank_agent` repo 工作時，**特別要求只要 10 個精選**：
`十大乾貨`、`十大好料`、`10 大乾貨`、`本周十大`、`給我 10 個`、`Top 10` 等。

（一般「本周乾貨/好料」走 `weekly-digest`；本 skill 專門做「限定 10 個」的精選。）

工作目錄為 repo 根目錄（home：`D:/github/Github_rank_agent`）。

## 組成規則（共 10 個，不重複）

| 類別 | 數量 | 怎麼挑 |
|------|------|--------|
| 🔥 熱門 | **5** | 本週榜單最熱（名次最前 / 週增最高） |
| 🎯 貼合你的興趣 | **3** | 從本週榜單，挑與你**過去標記/評價過**的 repo 最相干的（讀 `profile` 判斷主題相似度） |
| 💎 我的私房推薦 | **2** | 你（agent）依使用者背景，覺得對他**最實用**的 |

- **10 個彼此不重複**：一個 repo 只歸一類；先選熱門、再選貼合興趣（排除已選）、再選私房（排除已選）。
- **不足 10 個時按比例分配**：若本週可選的 repo < 10，依 **5:3:2** 比例縮放、**每類至少 1 個**、總數 = 可用數。
  （例：只有 6 個 → 3:2:1；只有 4 個 → 2:1:1。）

## 流程

### 1. 確認資料新鮮度
```bash
python main.py fetch --if-needed
```
本週已有非手動排行就會沿用、不重抓。

### 2. 讀候選與口味檔
```bash
python main.py digest      # 本週候選（名次/星標/週增/描述/[NEW][SEEN]/status）
python main.py profile     # 你過去標記/評價過的 repo + 描述（判斷「貼合興趣」用）
```
- 候選池 = 本週榜單（`digest` 列出的），排除已 `✅已研究` 的可斟酌。
- 若 `profile` 是空的（你還沒標記過任何東西）→ 「貼合你的興趣」這 3 個改用你（agent）的最佳推測，並如實說明「目前還沒有歷史偏好可參考」。

### 3. 選出 10 個並導讀
依組成規則挑好後，用**繁體中文、生動但不浮誇**導讀（語氣同 weekly-digest），分三塊呈現，**每筆說明入選理由**：

```
🏆 本周十大乾貨

🔥 熱門 Top 5
- <短名> — <一句重點>（<星標>⭐，本週 +<週增>）
...

🎯 貼合你的興趣（依你過去標記）
- <短名> — <重點>；**為何選它**：和你之前關注的 <某repo/主題> 同路
...

💎 我的私房推薦
- <短名> — <重點>；**為何實用**：<針對使用者的理由>
...
```

- 貼合興趣的每筆**務必點出**它對應到你過去哪個興趣/主題。
- 私房推薦每筆**說明為何對你實用**。
- 已標記的 repo 仍帶 `⭐想研究` / `🔬研究中` / `✅已研究` 記號。

### 4. 結尾提問
問使用者對哪些有興趣 → 對選中的執行：
```bash
python main.py interested <owner/name> [<owner/name> ...]
```

## 「進一步介紹」（深入導讀，先不標記）

使用者看完清單後說「**進一步介紹**」（某 repo 或名次）時：
1. 用 **WebFetch 讀該 repo** 的 `https://github.com/<owner/name>`（README / About），做一段**較完整的繁體中文介紹**：用途、主要功能/亮點、適用情境，必要時與同類工具比較。
2. **先不要做任何標記**（不要寫 interested）。
3. 介紹完再問：「要把它標記為『想進一步研究』嗎？」使用者說要才執行：
   ```bash
   python main.py interested <owner/name>
   ```

對照：使用者直接說「我對 X 有興趣」→ 直接標記；說「進一步介紹」→ 只導讀、不標記。

## 規則
- 回答一律繁體中文；DB 的 `description` 存乾淨英文。
- 10 個盡量分散、不重複；不足則按 5:3:2 比例、至少各一。
